# เกณฑ์ตรวจความเข้าใจและประเมินโครงการ

## หลังจบแต่ละบท

ให้ผู้เรียนทำสี่อย่าง: คาดเดาผลโดยไม่รัน, พิมพ์ตัวอย่างเอง, เปลี่ยนเงื่อนไขหนึ่งจุด, และอธิบายสาเหตุของ error ที่จงใจใส่ ถ้าทำได้เพียงคัดลอกแล้วรัน ให้ย้อนฝึกขั้นที่ยังอธิบายไม่ได้

คำตอบต่างจากเฉลยได้หากตรงพฤติกรรมที่โจทย์กำหนด

## จุดตรวจประจำ Phase

| Phase | หลักฐานที่ใช้ตรวจ |
|---|---|
| 1 | รายงานตัวเลขถูกต้อง ตรวจรายการว่างและขอบเขตได้ |
| 2 | test ตรวจจับกฎที่จงใจเขียนผิด และ refactor โดยผลเดิมยังถูก |
| 3 | hybrid pipeline ตรง Python reference และระบุการส่ง/คัดลอกข้อมูลได้ |
| 4 | raw benchmark, วิธีวัด, รุ่นเครื่องมือ และกรณีที่การปรับไม่ช่วย |
| 5 | เทียบ GPU/CPU ครบทั้งขนาดปกติและ tail แยกเวลาโอนข้อมูล |
| 6 | คนอื่นรันตามเอกสารได้ มีข้อจำกัดและแนวทางแก้ปัญหา |

## Rubric สำหรับ Capstone

| ด้าน | คะแนน | สิ่งที่ต้องแสดง |
|---|---:|---|
| ความถูกต้อง | 35 | reference, ขอบเขต, input เสีย และ numeric tolerance |
| ความเข้าใจภาษา | 25 | อธิบาย types, ownership, lifetime และ interface |
| หลักฐานประสิทธิภาพ | 20 | baseline ที่เหมาะสม หลายรอบ raw data และ end-to-end |
| การส่งต่อและสอน | 20 | ขั้นตอนรันชัด แหล่งอ้างอิงตรงรุ่น สาธิตและตอบเหตุผลได้ |

เกณฑ์เสนอ: อย่างน้อย 75/100 และด้านความถูกต้องอย่างน้อย 28/35 หากพบผลผิดที่ยังไม่แก้ ถือว่ายังไม่ผ่านแม้คะแนนรวมถึง ไม่ให้คะแนนเพิ่มเพราะเร่งความเร็วมากหากเปรียบเทียบคนละงาน
